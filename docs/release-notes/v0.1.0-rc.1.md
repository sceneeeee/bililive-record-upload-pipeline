# v0.1.0-rc.1 — Reproducible recording and upload integration

> Draft pre-release notes. Publish only after the target commit's CI, source archive and security checks have been reviewed.

## Overview

A self-hosted integration combining BililiveRecorder 2.18.0 and biliLive-tools 3.20.0 with reproducible patches, conservative cleanup, deployment examples and monitoring tools.

## Included

- Pinned upstream image digests and SHA256-verified bundle patching.
- Upload stream lifecycle and source identity patch.
- Immediate upload scheduling with per-live serialization and separate handled/raw pending request types.
- SQLite-backed sidecar cleanup with conservative task, callback, identity and open-FD checks.
- Docker Compose examples, systemd units, deployment preparation, monitoring and rollback scripts.
- Offline Python/Node.js tests and GitHub Actions checks.

## Evidence and limitations

- Historical production use exists for an ancestor workflow, including FLV segmentation, webhook/upload activity and repeated parent submission/edit operations.
- The historical scheduler bundle differs from this release candidate: the public version includes a handled/raw pending-type fix that is covered by offline regression tests but was not the production scheduler implementation.
- The historical cleaner and monitoring scripts differ from the public implementation. Historical production cleanup allowed final-failure deletion; the public cleaner defaults to retaining final failures.
- The current public revision has not completed full real-live end-to-end acceptance, public multipart playback verification, or a fresh-host install/maintenance/rollback rehearsal.
- Historical logs include storage-pressure and log-decoding incidents. Reliable retry recovery rates and complete public P-order evidence are unavailable.

Do not interpret historical ancestor operation or passing CI as production certification of this release candidate.

## Data safety

- No production credentials, environment files, recordings, databases, raw logs or server-specific configuration are included.
- Upload success does not imply Bilibili review approval or permanent remote availability.
- Irreversible deletion behavior must be reviewed before deployment; independent backups are recommended.
