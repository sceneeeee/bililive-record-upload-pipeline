# 验证范围与证据等级

本文区分四类证据：

- **CI / 离线测试**：在合成数据、锁定上游 bundle 或模拟对象上验证，不连接生产账号或服务器。
- **历史生产观察**：来自此前真实部署的匿名化日志、持久化台账和运行文件哈希；只能证明被观察到的历史祖先实现和具体事件。
- **当前公开版本生产验证**：必须将运行镜像、bundle SHA、维护脚本和配置逐项对应到当前公开提交，并验证目标行为。当前尚未完成。
- **未知（UNKNOWN）**：缺少可靠证据；不能当作零、失败或通过。

## 自动化测试

`bash tests/run.sh` 核对源码发布清单和两份重建 bundle，运行 Python 清理/部署保护/错误上游测试与 Node.js 实际方法模拟。测试数据使用临时目录和合成任务，不使用真实账号、房间、投稿或生产连接。

覆盖范围包括：

- 清理器：成功终态删除、失败默认保留、显式失败删除、取消、重试、父子/兄弟任务、handled/raw 回调、API 失联/重启、持久终态、缺失非终态、重复/崩溃恢复、文件替换、symlink/硬链接、删除退避、开放 FD、扫描失败和删除意图后的身份变化。
- 调度：同一直播串行、不同直播并行、handled/raw 双向请求、全类型请求、异常解锁、后处理后立即调度且不等待上传。
- 上传流：成功、失败、有限重试、取消及限速异常路径，检查流是否关闭。
- 部署：锁定文件、错误上游拒绝、部署准备保护。
- CI：固定上游镜像提取、Python/Node 测试、语法检查、Compose/systemd 校验、Gitleaks 目录与 Git 历史扫描。

CI 不含生产凭据、SSH 或部署步骤。

## 历史生产观察（不是当前公开版本验收）

此前部署的历史基线确有真实录播和投稿活动。匿名化审计观察到：

- 约 5 GiB 量级的 FLV 分段、Webhook/后处理相关事件和文件上传终态记录。
- 文件上传与父投稿/编辑操作均有成功及失败终态；同一稿件标识出现多次成功编辑操作，支持曾发生续传/合并类工作流。
- 历史生产镜像 digest 与当前锁定镜像一致；上传流补丁 bundle 的 SHA256 与公开版本一致。
- 历史生产调度 bundle 与当前公开版本不同。生产历史基线使用 dirty 标志，不能分别保留并发到达的 handled/raw 类型；当前公开版本改为按类型保存待办集合。公开版本的离线回归测试通过，历史基线在该合成反例中失败。该反例不能证明生产中实际发生了多少漏传。
- 历史生产清理器使用独立的 `sv-*` 服务和脚本，不是本仓库的 `pipeline-*` unit。历史策略允许删除最终失败源文件；当前公开旁路清理器默认保留失败，只有显式启用 `--delete-final-failure` 才开放该资格。
- 历史生产监控记录曾出现磁盘空间不足告警、日志读取/解码异常和上传失败。日志轮转与损坏使得部分历史窗口不完整；不能据此宣称连续无故障或计算可靠的重试恢复率。
- 历史台账存在成功任务对应的源文件 absent 记录，也有最终失败任务对应的历史删除记录。absent 不等于已证明由旁路清理器 unlink；历史删除不等于当前公开策略。

这些观察只用于解释项目来源、设计动机和差异。**历史生产祖先版本的运行不能替代当前公开 commit 的生产验证。** 生产主机路径、账号、房间、稿件标识、原始日志和数据库记录不属于公开证据。

## 已知限制与风险

- 中文秒级文件名仍可能在同秒重连时冲突；保留上游重名保护，不应仅为规避冲突擅自改变文件格式。
- 网络 EOF、404、TLS 和 socket reset 仍可能发生；补丁不能保证消除网络故障。
- 上游 `afterUploadDeletAction=delete` 的成功删除先于旁路清理器的全部检查；旁路保护不能追溯阻止上游已删除的文件。
- 文件 stat/FD 检查与 unlink 之间不是跨进程原子操作；录像目录必须只允许受信任业务进程写入。
- API 不提供可靠的全量持久上传队列。任务缺失、回调未结束或关联不明时应保守保留，不得通过清空台账解决。
- 小文件、封面、旁车和未知文件不自动等同于无用缓存；不能只按年龄、大小或“API 无任务”删除。
- 历史生产部署曾出现磁盘空间压力；将失败录像改为保留会增加存储需求，部署者应基于码率、积压和保留策略规划容量。
- 历史日志存在无效 JSON/读取异常，部分 Docker 日志也受轮转限制；没有日志不等于没有事件，日志行数也不等于独立任务数。

## 当前公开版本的验收边界

当前公开版本**尚未完成真实直播完整端到端验收，也未完成在新主机上的完整安装、维护窗口和回滚演练**。需要在独立环境或经明确审批的自然运行窗口中，验证：

1. 自然开播、FLV 分段持续增长及文件正常关闭。
2. Webhook、后处理、即时上传和周期扫描之间的关系。
3. handled/raw 并发请求不丢失类型，上传流在成功/失败/取消/限速路径均关闭。
4. 有限重试、父投稿状态、分 P 顺序和稿件合并。
5. 成功删除、最终失败保留、取消保留和未知状态保留。
6. 回调、兄弟任务、打开 FD、API 重启和清理台账恢复保护。
7. 新主机安装、维护窗口 guard、回滚及数据备份。

不要在生产环境主动断网、伪造 Webhook、触发失败删除或制造磁盘耗尽来完成测试。生产部署与 GitHub Release 是独立操作；CI 通过不构成生产部署授权。
